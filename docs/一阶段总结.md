# 六轮摇臂月球车导航感知项目一阶段总结

## 1. 项目概述

本阶段完成了一套基于 ROS 2 Humble 和 Gazebo Fortress 的六轮摇臂月球车导航感知仿真框架。系统面向 Livox Mid-360 激光雷达和奥比中光 Gemini 335 RGB-D 相机，支持平地、台阶、岩石障碍、楼梯迷宫和随机凸起迷宫等仿真地形。

仿真环境使用标准地球重力：

```text
9.80665 m/s²
```

上位机只生成底盘运动控制指令，通过 `/chassis/cmd_vel` 下发；电机分配、闭环驱动、急停和底层故障处理由下位机负责。Gazebo 中使用 `ros2_control` 模拟下位机，以便验证上位机的感知、定位、建图和导航算法。

本阶段主要目标包括：

- 建立尺寸和悬架结构较为清晰的六轮摇臂月球车模型；
- 建立 Mid-360、Gemini 335 的仿真数据链路；
- 比较二维投影、点云累计、ICP 和 IMU/轮速融合等建图路线；
- 在三维地图可视化条件下完成简单台阶和迷宫任务；
- 为 FAST-LIO、RTAB-Map、地形感知和 Nav2 保留完整工程接口。

## 3. 建图算法路线与测试结果

### 3.1 二维占据栅格建图

第一种测试方法是将 Mid-360 三维点云投影到二维平面，生成 `OccupancyGrid` 栅格地图。

基本过程为：

```text
Mid-360 点云
    ↓
按高度过滤并投影到 XY 平面
    ↓
二维占据栅格
    ↓
RViz 显示
```

实际测试中，地面、10 cm 左右的凸起、台阶边缘和墙体容易同时投影到二维地图。车辆发生俯仰和横滚时，地面点还会被错误投影为障碍物，导致地图中出现大面积密集、杂乱的占据点。

结论：

- 适合平整室内环境；
- 不适合直接表达本项目中的台阶和崎岖地形；
- 可作为 Nav2 二维代价地图的辅助数据，但不适合作为主要建图展示。

实现文件：

- [`src/lunar_rover_perception/scripts/simple_2d_mapper.py`](src/lunar_rover_perception/scripts/simple_2d_mapper.py)
- [`src/lunar_rover_navigation/rviz/mapping_2d.rviz`](src/lunar_rover_navigation/rviz/mapping_2d.rviz)

### 3.2 三维点云直接累计

第二种方法是根据里程计位姿，将每一帧雷达点云转换到固定坐标系并直接累计。

```text
当前帧点云 + 当前里程计位姿
           ↓
坐标变换到 odom/map
           ↓
累计点云
```

该方法可以快速得到墙面、通道和障碍物的大致三维轮廓，适合检查传感器安装方向和点云覆盖范围。但是它本质上不是完整 SLAM：

- 没有可靠的帧间配准；
- 没有位姿图优化；
- 没有回环检测；
- 里程计误差会永久保留在累计点云中。

因此测试中虽然可以看到三维地图外形，但车辆转弯和起伏后，墙面会出现重影和错层。

实现文件：

- [`src/lunar_rover_perception/scripts/assembled_3d_mapper.py`](src/lunar_rover_perception/scripts/assembled_3d_mapper.py)

### 3.3 ICP 里程计与 RTAB-Map

第三种方法使用 RTAB-Map 提供的 ICP Odometry 对相邻雷达点云进行匹配，并将 ICP 估计的相对运动作为 RTAB-Map 的里程计输入。

```text
/livox/points
    ↓
ICP Odometry
    ↓ /icp/odometry
RTAB-Map 位姿图与点云地图
    ↓
map → odom + 三维地图
```

ICP 通过寻找相邻点云之间的最佳刚体变换，估计车辆在两帧之间的位移和旋转。RTAB-Map根据该位姿连续放置点云，并在满足条件时进行图优化。

测试结果：

- 平地短距离直行时能够建立较清晰的墙体轮廓；
- 雷达点云较稀疏或视野重叠不足时，ICP约束较弱；
- 车辆经过凸起时，车体俯仰、横滚和高度同时变化；
- 地面可能被错误匹配为倾斜墙面；
- 转弯误差累积后，同一条直道会散成多条不同方向的直道；
- z轴出现持续上浮或下沉现象。

该现象说明，问题主要来自输入给 RTAB-Map 的 ICP 位姿已经发生漂移，而不是单纯的RViz显示问题。缺少稳定里程计和可靠回环时，RTAB-Map无法完全消除这种误差。

相关文件：

- 启动入口：[`src/lunar_rover_bringup/launch/icp_slam_3d_test.launch.py`](src/lunar_rover_bringup/launch/icp_slam_3d_test.launch.py)
- ICP配置：[`src/lunar_rover_localization/config/icp_odometry_mid360.yaml`](src/lunar_rover_localization/config/icp_odometry_mid360.yaml)

### 3.4 轮速里程计、IMU EKF与RTAB-Map

为改善ICP方法的高度和姿态漂移，本阶段实现了轮速里程计与 Mid-360 IMU 的 EKF 融合方案。

当前数据链路为：

```text
车轮关节状态
    ↓
wheel_odometry_node
    ↓ /wheel/odometry ────────────────┐
                                      │
Mid-360 IMU                           ├→ robot_localization EKF
    ↓                                 │
imu_covariance_node                   │
    ↓ /livox/imu/sanitized ───────────┘
                                      ↓
                            /odometry/filtered
                                      ↓
/livox/points ───────────────────→ RTAB-Map
                                      ↓
                         三维点云地图 + map→odom
```

当前 EKF 的使用方式为：

- 轮速里程计提供前向速度、偏航角速度和z轴约束；
- IMU提供横滚、俯仰及其角速度；
- 暂不直接融合IMU绝对yaw；
- IMU协方差由中间节点补全；
- RTAB-Map以 `base_footprint` 为平面运动基准；
- RTAB-Map启用 `Reg/Force3DoF=true`，抑制定位姿态中的z、roll和pitch长期漂移；
- 地形自身的高度仍通过雷达点云保留。

测试过程中对轮式里程计等效轮距进行了标定，当前值为：

```text
track_width = 0.375 m
```

一次原地转向测试结果约为：

| 数据源 | 旋转角度 |
| --- | --- |
| Gazebo真值 | 175.2° |
| EKF输出 | 176.4° |
| 轮速里程计 | 173.6° |

说明原地转向条件下，轮速偏航估计已基本准确。

改进效果：

- 地图整体持续下沉的现象显著减轻；
- 平地直行和原地转向的点云一致性提高；
- 车辆的短距离往返地图更集中；
- 车体真实起伏不会直接全部累积为地图坐标系的高度漂移。

仍存在的问题：

- 六轮车辆在崎岖地面转向时存在侧滑；
- 轮速里程计会把车轮滑动误认为真实偏航；
- 边行驶边转弯时，估计yaw仍可能大于Gazebo真值；
- 当前IMU节点只补全协方差和过滤非法四元数，没有完成完整的零偏在线估计；
- 尚未针对真实 Mid-360 IMU 噪声、时间同步和外参进行实车标定。

```text
Mid-360点云 + Mid-360 IMU
             ↓
          FAST-LIO
             ↓
       LIO里程计和配准点云
             ↓
  EKF融合LIO与轮速里程计
             ↓
          RTAB-Map
             ↓
      三维地图与回环优化
```

该方案中：

- FAST-LIO负责点云与IMU紧耦合的激光惯性里程计；
- `lio_odom_adapter`负责坐标系和消息格式适配；
- EKF融合LIO与轮速信息；
- RTAB-Map融合雷达注册点云和RGB-D数据，负责地图管理与回环。

这条链路的工程配置已经存在，但不是本阶段反复运行和对比后最终采用的演示链路。其真实稳定性仍需继续测试，尤其需要处理：

- Mid-360时间戳和IMU时间同步；
- 雷达与IMU外参；
- FAST-LIO参数；
- 仿真雷达数据与真实Livox扫描模式之间的差异；
- 回环检测和地图重定位。

## 4. 导航算法路线与测试结果

### 4.1 自动上一级台阶任务

本阶段实现了简单的台阶搜索与攀爬任务：

1. 从雷达点云中搜索疑似台阶；
2. 调整车辆朝向；
3. 向台阶行驶；
4. 车辆完成一级台阶攀爬后停止。

该任务用于验证传感器数据、底盘运动指令和摇臂悬架运动是否能够形成闭环，并不等同于完整的全局路径规划。

### 4.2 直线往返漂移测试

为了单独观察定位建图漂移，项目实现了直线往返测试任务：

1. 原地旋转并寻找第一条可通行道路；
2. 沿道路直行指定距离；
3. 原地转向约180°；
4. 返回起点；
5. 再次掉头并重复。

最终测试距离调整为0.8 m，用于放大观察：

- 原地转向角误差；
- 往返点云重合程度；
- z轴是否持续漂移；
- 轮速和EKF的偏航差异。

### 4.3 迷宫实时建图导航

当前实际演示的迷宫导航采用自定义反应式循墙算法，而不是Nav2全局路径规划。

基本逻辑为：

1. 将雷达点云转换到 `base_link` 坐标系；
2. 统计前方、左侧和右侧扇区的墙体距离；
3. 过滤低于约8 cm的点，尽量忽略地面半球障碍；
4. 默认采用右手循墙；
5. 前方受阻时，优先选择开放方向转弯；
6. 直行时根据目标航向和左右墙距离进行居中修正；
7. 车体倾斜较大时降低行驶速度。

该方法优点是逻辑简单，不依赖预先建立的完整地图，在规则迷宫中能够运行。缺点是：

- 不是全局最优路径规划；
- 没有显式记录已走过的拓扑节点；
- 复杂死循环迷宫可能反复绕行；
- 地面凸起会通过车辆姿态和滑移间接影响方向控制；
- 墙面被误识别或点云过稀时可能作出错误转弯。

当前迷宫任务还有一个重要的实验设置：任务控制器使用 Gazebo 真值里程计判断车辆航向，而建图使用 EKF 输出。这样可以把“导航控制失败”和“建图定位漂移”分开观察。

因此，本阶段迷宫演示证明了以下内容：

- 三维建图与车辆运动能够同时运行；
- 雷达循墙逻辑能够控制车辆通过部分迷宫；
- 建图链路能够在车辆运动过程中实时更新。

但它还不能证明：

- 车辆仅依靠估计位姿即可稳定完成迷宫导航；
- 当前定位精度已经达到实车长期自主运行要求；
- Nav2全局规划闭环已经完成验证。

### 4.4 Nav2工程框架

仓库中已经建立 Nav2 配置，包含：

- `SmacPlanner2D` 全局规划器；
- `RegulatedPurePursuitController` 路径跟踪控制器；
- `VoxelLayer` 三维障碍物投影；
- 自定义 `TerrainLayer` 地形可通行性代价层；
- `InflationLayer` 障碍膨胀层；
- 速度平滑；
- 碰撞监控；
- 行为树导航和恢复行为。

地形感知节点计划融合雷达点云和深度相机点云，生成 `/terrain/traversability`，再由自定义 `TerrainLayer` 写入 Nav2 代价地图。

本阶段完成了相应工程文件和接口，但最终迷宫演示使用的是自定义循墙任务，Nav2完整自主规划链路尚未作为最终效果进行充分验证。

## 8. 一阶段结论

本阶段已经完成：

- ROS 2 Humble与Gazebo Fortress仿真环境；
- 六轮摇臂月球车模型及可动悬架；
- Mid-360雷达、IMU和Gemini 335深度相机仿真接口；
- 平地、台阶、岩石和可达迷宫地形；
- 二维地图、三维累计地图和ICP建图对比；
- 轮速与IMU EKF定位链路；
- RTAB-Map三维点云地图显示；
- 自动上一级台阶任务；
- 直线往返漂移诊断任务；
- 简单迷宫循墙建图任务；
- FAST-LIO、地形感知和Nav2工程框架。

当前最明显的改进是：轮速/IMU EKF配合平面约束后，z轴持续漂移得到明显抑制，原地转向精度也经过标定。

当前主要问题是：

- 崎岖地形移动转弯时仍存在轮速侧滑误差；
- IMU yaw尚未形成可靠融合；
- RTAB-Map回环和长期地图一致性尚未充分验证；
- 当前迷宫任务仍使用Gazebo真值辅助控制；
- Nav2与地形代价层尚未完成完整闭环测试；
- 仿真传感器只能用于算法验证，不能代替实机标定。

下一阶段建议优先完成：

1. 标定Mid-360雷达、IMU和车体之间的外参及时间同步；
2. 完整验证FAST-LIO并比较其与轮速/IMU EKF的轨迹误差；
3. 引入可靠的偏航观测或滑移修正，解决崎岖地形转向误差；
4. 增加真实闭环和地图重定位测试；
5. 取消迷宫控制中的Gazebo真值依赖；
6. 打通地形感知、Nav2代价地图、全局规划和底盘控制闭环；
7. 在真实Mid-360、Gemini 335和下位机上重新标定全部参数。

总体而言，本项目目前已经形成一套可运行、可视化、可继续扩展的ROS 2月球车导航感知工程框架，但定位建图和自主导航仍处于仿真算法验证阶段，尚不能视为复杂崎岖环境下的最终可靠方案。
