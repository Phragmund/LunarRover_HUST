<a id="1-task"></a>
# 1. 任务定义与总体目标

## 1.1 项目背景

系统主体是一台在月球熔岩管道模拟场景中运行的移动月球车。

导航环境已知特征包括：

- 管道整体直径约 1.5 m；
- 可行驶区域宽约 1 m；
- 沙土地面；
- 存在半埋砖石、月坑等复杂局部地形；
- MID-360 固定于车体用于定位和环境感知；
- Gemini 335L 拟安装在机械臂末端；
- 机械臂与 RGB-D 相机除了辅助地形感知，还需要完成目标抓取任务。

新增操作任务要求：

- 目标物随机布设在洞穴环境内；
- 目标可能放在地面；
- 目标也可能布设在岩壁上；
- 墙面目标高度不超过约 500 mm；
- 车辆需要在导航过程中自主发现视野内目标；
- 自主判断目标是否可抓；
- 必要时移动车体到适合抓取的位置；
- 自主控制机械臂抓取；
- 将目标存放到车载储物区域；
- 抓取结束后继续导航 / 搜索。

因此，该系统已经不再只是“自主移动机器人”，而属于典型的：

> **Mobile Manipulator（移动操作机器人）**

核心问题可拆为：

1. **Localization**：车在哪里？
2. **Navigation**：车应该怎么移动？
3. **Target Search**：目标在哪里？
4. **Target Localization**：目标的三维位置和姿态是什么？
5. **Reachability**：当前车体位置能不能抓？
6. **Grasp Planning**：夹爪应该从哪里、以什么姿态抓？
7. **Motion Planning**：机械臂如何无碰撞到达？
8. **Visual Servoing**：最后阶段如何消除视觉、标定与机械误差？
9. **Grasp Verification**：到底抓到了没有？
10. **Storage**：抓到后放在哪里？
11. **Task Orchestration**：所有状态如何自动切换与失败恢复？

<a id="3-eye-in-hand"></a>
# 3. 为什么机械臂末端 RGB-D 相机适合同时承担地形感知与抓取

把 Gemini 335L 装到机械臂末端属于经典的：

> **Eye-in-Hand（眼在手上）**

结构。

相对于固定车体相机，它的优势是：

1. **导航时可以朝前下方观察地面**
   - 补充 MID-360 的近场高密度地形点云；
   - 观察砖石、坑沿和局部地形。

2. **发现目标后可以主动改变视角**
   - 目标被遮挡时绕到侧面；
   - 地面目标可以从上方观察；
   - 墙面目标可以从正面 / 斜侧方观察。

3. **抓取前可以近距离精定位**
   - 不依赖远距离检测的初始坐标；
   - 降低 LIO 漂移、车轮滑移、机械臂挠曲造成的抓取误差。

4. **抓取过程中可以形成视觉闭环**
   - 相机随末端一起运动；
   - 可持续观察目标在相机坐标系中的相对位置。

5. **同一相机可以完成多任务复用**
   - terrain perception；
   - target search；
   - 6DoF pose；
   - grasp perception；
   - visual servo；
   - grasp verification。

最大的代价是：

- 相机位姿不再固定；
- 必须有机械臂关节编码器；
- 必须做好 hand-eye calibration；
- 深度帧与 `joint_states` 必须正确时间对齐；
- 机械臂快速运动会引入运动模糊与点云变形；
- 不应在机械臂快速扫动时无条件把深度点云融合进导航地形地图。

<a id="5-calibration"></a>
# 5. 坐标系、手眼标定与移动相机位姿估计

这是移动相机抓取中最关键的基础。

## 5.1 推荐 TF 链

```text
map
 └── odom
      └── base_link
           ├── mid360
           │
           └── arm_base
                └── joint_1_link
                     └── joint_2_link
                          └── ...
                               └── wrist_link
                                    └── gemini_link
                                         ├── depth_optical_frame
                                         ├── color_optical_frame
                                         └── imu_frame
```

## 5.2 相机实时位姿

机械臂编码器给出关节角：

\[
q(t)=
[q_1(t),q_2(t),...,q_n(t)]
\]

通过正运动学得到：

\[
{}^{base}T_{wrist}(q(t))
\]

手眼标定得到固定相机安装变换：

\[
{}^{wrist}T_{camera}
\]

则：

\[
{}^{base}T_{camera}(t)
=
{}^{base}T_{wrist}(q(t))
{}^{wrist}T_{camera}
\]

关键思想：

> 相机在机械臂上运动不是问题，只要每一帧相机数据都能匹配到该时刻准确的机械臂位姿。

## 5.3 Eye-in-Hand Hand-Eye Calibration

安装机械结构不需要做到“装上去就是 0.1° / 0.1 mm”。

更合理的是：

> **机械结构负责装牢，标定软件负责装准。**

MoveIt 官方提供 Eye-in-Hand Hand-Eye Calibration 教程：

- [MoveIt Hand-Eye Calibration 官方教程](https://moveit.picknik.ai/main/doc/examples/hand_eye_calibration/hand_eye_calibration_tutorial.html)
- [MoveIt2 Tutorials 中的 Hand-Eye Calibration 源码教程](https://github.com/moveit/moveit2_tutorials/blob/main/doc/examples/hand_eye_calibration/hand_eye_calibration_tutorial.rst)

官方教程说明，eye-in-hand 情况下需要采集多组：

- base → end-effector；
- camera → calibration target；

姿态对。

MoveIt 教程指出，至少需要多组不同姿态，并应包含不同旋转轴；实际通常采集十几组姿态后结果趋于稳定。

### 推荐实际标定流程

1. 固定 AprilGrid / ArUco / ChArUco 等平面标定板；
2. 机械臂移动到 15～30 个不同姿态；
3. 保证：
   - 有明显 yaw / pitch / roll 变化；
   - 不要全部只绕同一个轴转；
   - 距离和视角有一定变化；
4. 计算：
   \[
   {}^{wrist}T_{camera}
   \]
5. 保存到 URDF / YAML；
6. 用已知物体或标定板做验证；
7. 检查相机点云投影到机械臂坐标系后是否重合。

## 5.4 机械臂挠曲问题

即使 hand-eye 外参静态准确，机械臂实际工作时仍可能因为：

- 末端 Gemini 重量；
- 夹爪重量；
- 目标物重量；
- 电缆拖拽；
- 减速器间隙；
- 机械臂刚度不足；

产生姿态偏差。

因此建议：

\[
T_{camera}^{real}
\approx
T_{camera}^{FK}
\cdot
\delta T
\]

其中：

- FK 提供 nominal pose；
- IMU / 视觉提供 residual correction。

官方数据手册公开的 IMU 指标包括：

## 6.2 Orbbec ROS2 驱动

官方 ROS2 Wrapper：

- [OrbbecSDK_ROS2 GitHub](https://github.com/orbbec/OrbbecSDK_ROS2)

目前官方仓库对 Gemini 335L 有明确支持，并建议新项目使用 v2 系列分支。

## 6.3 IMU 的正确定位

Gemini IMU 不应取代机械臂关节编码器。

推荐职责：

| 量 | 主要来源 |
|---|---|
| 相机 x/y/z | 机械臂 FK |
| 相机 yaw | 机械臂 FK + 视觉 |
| 相机 roll/pitch | FK + IMU 辅助 |
| 高频角速度 | Gemini Gyro |
| 末端动态异常 | IMU |
| 长期绝对 6DoF | FK + 外部视觉几何 |

原因：

- 加速度计通过重力可约束 roll / pitch；
- gyro 可观测短时角变化；
- yaw 缺少绝对参考，长期积分会漂；
- IMU 二次积分求位置会快速漂移。

因此更合理的是估计：

\[
\delta R_{imu}
\]

然后：

\[
R_{camera}^{corrected}
=
R_{camera}^{FK}
\delta R_{imu}
\]

而不是：

\[
T_{camera}=T_{IMU-only}
\]

## 6.4 时间同步比静态安装精度更重要

假设机械臂角速度：

\[
30^\circ/s
\]

若 depth 时间戳与 joint state 偏差：

\[
50ms
\]

则姿态误差：

\[
30^\circ/s \times 0.05s=1.5^\circ
\]

在 1～2 m 观测距离上已经足以产生厘米级空间误差。

因此每一帧深度图必须使用：

\[
q(t_{depth})
\]

而不是“ROS 当前最新的 joint state”。

### 建议方法

建立 buffer：

```text
JointState Buffer
LIO Pose Buffer
Camera Frame Timestamp
```

每次收到 RGB-D：

1. 读取 frame timestamp；
2. 对机械臂关节位置做插值：
   ```text
   q(t_depth)
   ```
3. 对车体 pose 做插值：
   ```text
   T_map_base(t_depth)
   ```
4. 计算：
   ```text
   T_map_camera(t_depth)
   ```
5. 再把点云 / 目标坐标转换到 map 或 base。

<a id="7-search"></a>
# 7. 纯视觉目标搜索：如何在洞穴中“找到目标”

“纯视觉寻找目标”建议理解为：

> 不依赖 LiDAR 识别目标类别，而是由机械臂相机 RGB 图像主动扫描环境，通过视觉检测器发现目标。

## 7.1 搜索模式

建议定义机械臂多个离散 Search Pose：

```text
SEARCH_FRONT_LOW
SEARCH_FRONT
SEARCH_LEFT
SEARCH_RIGHT
SEARCH_WALL_LEFT
SEARCH_WALL_RIGHT
```

例如：

```text
            Camera
        ↙     ↓     ↘

      left  front  right

        ground / wall
```

导航时可以使用：

- 一个默认 `navigation_camera_pose` 持续向前下方；
- 每经过一定距离；
- 或进入新的局部区域；
- 或当前视野很差时；

执行短暂 Search Sweep。

## 7.2 搜索不应阻塞所有导航

可以分为两种模式：

### Continuous Passive Search

车辆正常低速导航：

```text
RGB → detector
```

若目标置信度超过阈值，则：

```text
TARGET_CANDIDATE
```

### Active Search

当任务要求“搜索所有目标”时：

```text
STOP / SLOW
↓
arm scan left
↓
arm scan center
↓
arm scan right
↓
merge detections
```

## 7.3 目标发现后的第一反应

不要立刻抓。

应该：

```text
detect
↓
confirm across frames
↓
estimate rough 3D
↓
record target
↓
check reachable
```

推荐多帧确认：

- 连续 N 帧检测；
- 类别一致；
- 3D 位置聚类一致；
- 置信度超过阈值。

这样可显著降低：

- 岩石纹理误识别；
- 灯光反光；
- 运动模糊；
- 一帧误检。

<a id="8-detection"></a>
# 8. 目标检测、实例分割与目标记忆

## 8.1 Detection 还是 Instance Segmentation？

对于抓取，推荐：

> **优先 Instance Segmentation，而不仅仅是 Bounding Box。**

原因：

Bounding Box：

```text
┌─────────────┐
│ wall OBJECT │
│ OBJECT wall │
└─────────────┘
```

其中会包含：

- 地面；
- 墙；
- 邻近石头；
- 其他背景。

Mask 则能更精确提取目标对应深度点：

```text
mask ∩ depth
      ↓
target-only point cloud
```

这对：

- 目标三维质心；
- PCA；
- Point Cloud；
- GraspNet；
- Contact-GraspNet；

都更有利。

<a id="9-rgbd"></a>
# 9. RGB-D 从二维检测到三维目标位置

## 9.1 像素反投影

像素：

\[
(u,v)
\]

深度：

\[
Z=D(u,v)
\]

相机内参：

\[
K=
\begin{bmatrix}
f_x&0&c_x\\
0&f_y&c_y\\
0&0&1
\end{bmatrix}
\]

则：

\[
X=\frac{(u-c_x)Z}{f_x}
\]

\[
Y=\frac{(v-c_y)Z}{f_y}
\]

\[
\mathbf p_c=[X,Y,Z]^T
\]

## 9.2 不要只取 Bounding Box 中心深度

因为 bbox 中心可能：

- 正好是孔洞；
- 反光；
- 没有深度；
- 对应背景。

推荐：

```text
instance mask
   ∩
valid depth
   ↓
point set
```

然后：

- median depth；
- trimmed mean；
- RANSAC；
- DBSCAN；

去除异常点。

## 9.3 目标粗定位

搜索阶段只需要：

\[
{}^{base}\mathbf p_{object}
\]

不一定需要完整姿态。

由：

\[
{}^{base}T_{object}
=
{}^{base}T_{camera}
{}^{camera}T_{object}
\]

即可把目标放到车体坐标系。

需要全局记忆时：

\[
{}^{map}T_{object}
=
{}^{map}T_{base}
{}^{base}T_{camera}
{}^{camera}T_{object}
\]

<a id="10-base-approach"></a>
# 10. 目标不在机械臂工作空间时：底盘自主靠近

机械臂工作空间有限。

不要使用：

> “目标发现后机械臂尽量伸过去”

的策略。

更合理：

```text
Target Pose
    ↓
Reachability Check
    ↓
Is grasp workspace valid?
    ├─ YES → manipulate
    └─ NO  → compute base approach pose
```

## 10.1 Manipulation Base Pose

给目标定义合适的底盘停靠区域。

例如：

\[
d_{target-base}\in[d_{min},d_{max}]
\]

还应考虑：

- 机械臂安装在车体哪一侧；
- 机械臂最大水平伸展；
- 机械臂奇异位置；
- 相机视野；
- 岩壁碰撞；
- 底盘宽度；
- 坑 / 石块。

所以不能只计算一个单独坐标。

更好的是生成多个候选：

```text
base_pose_1
base_pose_2
base_pose_3
...
```

每一个计算：

\[
Score=
w_r S_{reach}
+w_n S_{navigation}
+w_c S_{collision}
+w_v S_{visibility}
+w_m S_{manipulability}
\]

选最优。

## 10.2 到达后必须重新检测

远距离目标坐标不能直接用于最终抓取。

因为靠近过程中：

- LIO 会漂；
- 沙地会打滑；
- target map pose 有误差；
- 相机视角变化；
- 机械臂 FK 有误差。

所以：

```text
BASE_APPROACH
↓
STOP
↓
RE-DETECT
↓
RE-LOCALIZE
```

是强制步骤。

<a id="11-active-vision"></a>
# 11. 主动视觉：机械臂如何移动相机改善观测

机械臂相机最大的优势是：

> **机器人可以主动改变“怎么看”，而不只是被动接受一个坏视角。**

这就是 Active Vision。

## 11.1 为什么需要 Active View

目标可能：

- 被石头挡住；
- 靠墙太近；
- 部分埋在沙里；
- 只能看到一个侧面；
- 抓取面不可见。

第一次视图：

```text
camera
     \
      \
       █?        object partially occluded
```

可以改变为：

```text
View A    View B    View C
   \        ↓        /
       [ object ]
```

## 11.2 第一版：离散候选视角

不需要一开始实现强化学习 NBV。

可预定义：

```text
yaw offsets:
-30°, -15°, 0°, +15°, +30°

pitch offsets:
-20°, 0°, +20°
```

从中选择机械臂可达且无碰撞的候选。

评价：

\[
S_{view}=
w_1 S_{visible-area}
+w_2 S_{depth-valid}
+w_3 S_{grasp-quality}
-w_4 S_{motion-cost}
-w_5 S_{collision-risk}
\]

## 11.3 多视角点云融合

每个视角取得目标点云：

\[
P_1,P_2,...,P_n
\]

利用相机 TF 变换到同一目标 / base 坐标系：

\[
P_{merged}
=
\bigcup_i
{}^{base}T_{camera,i}P_i
\]

可用于：

- 补足遮挡；
- 完善表面；
- 提高 grasp proposal 稳定性。

## 11.4 可参考研究

### Active Vision for Grasp Synthesis

论文：

- [Grasp Synthesis for Novel Objects Using Heuristic-based and Data-driven Active Vision Methods](https://arxiv.org/abs/2104.11372)

该工作研究：

- 机械臂搭载深度相机；
- 主动调整 viewpoint；
- 提升抓取生成质量。

其开源仿真平台：

- [2021ActiveVision GitHub](https://github.com/galenbr/2021ActiveVision)

### ACE-NBV

论文：

- [Affordance-Driven Next-Best-View Planning for Robotic Grasping (ACE-NBV)](https://arxiv.org/abs/2309.09556)
- [PMLR 正式论文](https://proceedings.mlr.press/v229/zhang23i/zhang23i.pdf)

其核心思路是：

> 选择能够提高抓取 affordance / grasp quality 的下一最佳视角。

这非常适合后续把“机械臂找一个更好视角”升级成论文工作。

实践中可做：

\]

## 12.4 抓取模板

```text

```

数学表达：

\[

\]

在线：

\[

=
{}^{base}T_{object}

> **FoundationPose + Grasp Templates**

<a id="14-hybrid"></a>
# 14. 推荐路线 C：目标分割 + 已知位姿/通用抓取的混合方案

本项目最推荐：

```text
             RGB
              ↓
     Instance Segmentation
              ↓

              ↓

MANUAL_FALLBACK
```

最后所有算法都进入同一个 Candidate Filter。

<a id="15-ground-wall"></a>
# 15. 地面目标与墙面目标的差异化抓取策略

你们的目标可能：

1. 在沙地；
2. 在不超过 500 mm 的墙面。

两种情况必须区别处理。

## 15.1 地面目标

典型：

```text
       camera
         \
          \
       gripper
          ↓

        [OBJ]
~~~~~~~~~~~~~~~~ sand
```

### 优先 grasp

- top grasp；
- oblique top grasp；
- side grasp（空间允许时）。

### 风险

- 夹爪手指碰地；
- wrist 碰沙地；
- 相机离地太近；
- 目标部分埋沙导致 grasp width 错误；
- 点云里混入地面。

### 建议

拟合 ground plane：

\[
\pi_g:
a_gx+b_gy+c_gz+d_g=0
\]

抓取候选必须满足：

\[
d(gripper,\pi_g)>margin
\]

## 15.2 墙面目标

典型：

```text
wall
████████████
████ [OBJ] ← gripper
████████████
```

先利用 depth / MID-360 拟合 wall plane：

\[
\pi_w:
a_wx+b_wy+c_wz+d_w=0
\]

墙法向：

\[
\mathbf n_w=
[a_w,b_w,c_w]^T
\]

### 优先 approach

通常让夹爪 approach 尽量远离墙内方向。

如果目标从墙面突出：

```text
wall
██████
██████ [OBJ]
██████      ← gripper
```

可优先：

- frontal grasp；
- side grasp；
- oblique grasp。

### 必须检查

- finger sweep 是否穿入墙；
- wrist 是否碰墙；
- camera 是否碰墙；
- 抓取后 retreat 有没有空间。

## 15.3 场景分类

可根据目标附近 dominant plane：

- normal 接近 vertical → wall target；
- normal 接近 gravity → ground target。

然后选择对应 grasp policy。

必须经过：

## 16.1 推荐评分

\[

w_pS_{perception}
+w_gS_{grasp}
+w_rS_{reach}
+w_mS_{manipulability}
-w_cC_{collision}
-w_sC_{singularity}
-w_jC_{jointlimit}
\]

## 16.2 碰撞对象

MoveIt Planning Scene 至少应包含：

- 车体；
- 机械臂；
- 夹爪；
- 岩壁；
- 地面；
- 可见大型石块；
- 目标物；
- 储物箱。

## 16.3 Pre-Grasp

不要让规划器直接运动到最终夹持位。

定义：

\[
T_{pre}
=
T_{grasp}
\cdot
Trans(0,0,-d_{approach})
\]

例如：

```text
Pre-Grasp
   ↓ 10~20cm
Approach
   ↓
Grasp
```

<a id="18-servo"></a>
# 18. Eye-in-Hand 视觉伺服：最后 10～20 cm 的闭环对准

这是提高实际成功率的重要模块。

## 18.1 为什么需要 Visual Servo

即使：

- FoundationPose 很准；
- hand-eye 很准；
- MoveIt IK 很准；

仍存在：

- 关节 backlash；
- 机械臂柔性；
- 目标 pose 噪声；
- 深度噪声；
- 相机支架误差；
- 目标轻微移动。

因此推荐：

```text
Global Motion Planning
     ↓
Pre-Grasp
     ↓
Visual Servo
     ↓
Final Grasp
```

## 18.2 PBVS

Position-Based Visual Servoing。

持续估计：

\[
{}^{camera}T_{object}(t)
\]

已知期望目标相对相机 / 夹爪关系：

\[
{}^{camera}T_{object}^{desired}
\]

计算误差：

\[
\Delta T=
T_{current}^{-1}T_{desired}
\]

提取：

```text
Δx Δy Δz
Δroll Δpitch Δyaw
```

生成末端小速度：

\[
\mathbf v=
-K_p\mathbf e
\]

## 18.3 MoveIt Servo

官方：

- [MoveIt Realtime Servo](https://moveit.picknik.ai/main/doc/examples/realtime_servo/realtime_servo_tutorial.html)

MoveIt Servo 可接受：

- joint commands；
- end-effector velocity；
- target pose；

并提供：

- collision checking；
- singularity handling；
- joint limit handling。

因此可以：

```text
FoundationPose tracker
        ↓
Pose Error
        ↓
PBVS Controller
        ↓
TwistStamped
        ↓
MoveIt Servo
        ↓
Robot Arm
```

## 18.4 控制频率

第一版不一定追求极高频。

可：

```text
Perception: 10~30 Hz
Servo command: 20~100 Hz
```

具体取决于：

- 相机；
- GPU；
- 机械臂控制器；
- FoundationPose / tracker 延迟。

## 18.5 最后几厘米的视觉遮挡

夹爪可能挡住目标。

因此建议：

1. 相机不要完全安装在夹爪正后方；
2. 做一定角度 / 位置偏置；
3. 到达距离目标约 20～50 mm 时：
   - 保存最后稳定 pose；
   - 短距离低速 open-loop approach；
   - close gripper。

<a id="19-verify"></a>
# 19. 夹爪闭合、抓取确认与失败重试

全自动系统不能：

```text
close gripper
↓
assume success
```

## 19.1 可用反馈

### 夹爪位置

若夹爪完全闭合：

```text
width ≈ 0
```

可能意味着空抓。

### 电机电流 / 力

闭合过程中：

```text
current ↑
while width > 0
```

可认为夹到东西。

### 视觉

抓取后抬起：

```text
LIFT 50~100 mm
```

再观察：

- 原目标位置是否为空；
- 夹爪附近是否检测到目标。

## 19.2 多信号融合

例如：

```text
gripper_contact = true
AND
object_disappeared_from_ground = true
AND
object_near_gripper = true
```

则：

```text
GRASP_SUCCESS
```

## 19.3 失败恢复

```text
GRASP_FAIL
    ↓
OPEN
    ↓
RETREAT
    ↓
RE-DETECT
    ↓
ACTIVE_VIEW
    ↓
new grasp candidate
    ↓

```

设置最大重试次数，例如：

```text

```

超过后：

```text

```

记录后继续任务，避免死循环。

<a id="23-lighting"></a>
# 23. 弱光熔岩洞环境下的视觉与补光设计

这是实际系统中很容易被低估的问题。

深度和 RGB 的需求不同。

即使深度系统能够在弱光中工作：

> RGB 目标检测仍然需要足够可见光和合理曝光。

## 23.1 推荐补光

在 camera / wrist 附近安装：

- LED white light；
- 漫射罩；
- 尽量避免极强点光源；
- 避免相机运动时产生大面积阴影。

## 23.2 补光必须随相机

相机装在机械臂上后，车体固定灯可能：

- 相机看左边，灯照前方；
- 相机接近墙，目标处于阴影。

因此建议：

```text
Camera + Local LED
```

共同安装在 wrist。

## 23.3 曝光策略

Navigation 搜索：

- 优先高帧率；
- 不允许太长 exposure 导致 motion blur。

Manipulation：

- 底盘停止；
- 机械臂低速；
- 可以适当提高曝光质量。

<a id="28-failure"></a>
# 28. 典型失败模式与工程对策

| 失败 | 可能原因 | 建议 |
|---|---|---|
| RGB 找不到目标 | 洞内弱光 | wrist LED |
| Depth 空洞 | 反光 / 几何问题 | 多视角 / active view |
| 目标 3D 飘 | timestamp 错 | joint interpolation |
| 相机点云随机械臂漂 | hand-eye 不准 | 重新标定 |
| 伸臂后位置偏 | arm flex | IMU residual + visual servo |
| FoundationPose 抖 | mask 差 / depth 差 | better segmentation + multi-frame |
| 抓到墙 | 未建 wall collision | plane / PlanningScene |
| 手指碰地 | ground plane 未过滤 | grasp clearance |
| GraspNet 抓背景 | 未用 target mask | instance crop |
| MoveIt 无解 | grasp pose 差 | multiple candidates |
| 最后偏几 cm | open-loop | visual servo |
| 空抓仍认为成功 | 无 verify | current + width + vision |
| 同目标反复抓 | 无 target memory | target manager |
| 车靠近后抓偏 | 使用旧 target pose | mandatory re-detection |
| 机械臂扫动污染地形图 | dynamic camera point cloud | manipulation mode disable terrain fusion |

# 29. 可以进一步研究的高级方向

系统基础链路稳定后，可进一步做成具有研究价值的模块。

## 29.1 Active Next-Best-View

目标：

\[
\arg\max_{view} ExpectedGraspQuality(view)
\]

让机械臂根据：

- 遮挡；
- 点云完整度；
- grasp score；

自动寻找下一个视点。

参考：

- [Active Vision Grasp Synthesis](https://arxiv.org/abs/2104.11372)
- [ACE-NBV](https://arxiv.org/abs/2309.09556)

机械臂绕目标拍摄：

```text
P1 + P2 + ... + Pn
```

构造更完整的局部表面。

可用于未知岩石样目标。

## 29.3 Joint Base-Arm Planning

当前推荐：

```text
move base
↓
stop
↓
move arm
```

高级方向可变成：

> base + arm jointly optimize

联合状态：

\[
[x,y,\theta,q_1,...,q_n]
\]

不过复杂度显著提高，不建议第一版做。

## 29.4 Vision-Language 搜索

> “寻找红色带标签的样品”  
> “寻找类似岩芯的圆柱形目标”

可以研究 open-vocabulary detection / VLM。

当前任务如果目标类别固定，没必要第一版引入。

## 29.5 Grasp Risk Prediction

不仅使用 grasp network score，还加入：

- wall clearance；
- ground clearance；
- target confidence；
- camera confidence；
- joint manipulability；
- arm flex risk。

统一：

\[
P(success|\text{perception, grasp, geometry})
\]

# 32. 项目最值得形成特色的部分

如果从“项目展示”和“论文/比赛技术亮点”两个角度看，这套系统最有特色的不只是“用机械臂抓一个东西”，而是：

> **同一台机械臂末端 RGB-D 相机在导航与操作两种任务间进行主动重构：导航时作为可变视角地形感知传感器，发现目标后转变为 eye-in-hand 操作视觉，通过主动视角、6DoF 定位和视觉伺服完成抓取。**

可以形成完整闭环：

```text
移动导航
   ↓
视觉发现
   ↓
目标粗定位
   ↓
底盘接近
   ↓
主动观察
   ↓
目标精定位
   ↓
抓取规划
   ↓
视觉闭环对准
   ↓
抓取确认
   ↓
车载存放
   ↓
恢复导航
```

建议实际开发时遵循：

> **先做可靠闭环，再逐步加入高级智能。**

最先需要跑通的是：

1. 目标真的能稳定识别；
2. RGB-D 能把目标变成准确 3D 坐标；
3. 移动相机 TF 不漂；
4. 机械臂能到 pre-grasp；
5. 最后视觉闭环能修掉厘米级误差；
6. 夹爪能确认抓没抓到；
7. 无法抓取时系统能够安全退出而不是死循环。

这些基础可靠后，再加入 FoundationPose、GraspNet、Next-Best-View，系统复杂度才是可控的。
