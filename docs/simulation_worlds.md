# Simulation Worlds

The default simulation test world is `image_cave`.

`image_cave` is the main navigation and driving test map. It contains the
generated cave wall topology from the red-point reference image, plus the
current triangular pseudo-surface terrain:

- 186 static wall segments generated from the annotated cave graph.
- Cave topology scale: the reference-image channel estimate is scaled to about
  1.12 m between opposing wall centerlines. With the current 0.12 m wall
  thickness, typical clear corridor width is about 1.0 m.
- A watertight triangular terrain mesh raised around 1 m above the world origin.
- Terrain triangle edge length: 0.2 m.
- Base terrain height range: 0.95 m to 1.05 m.
- Pit obstacles: 100 spawn-connected corridor pits generated by lowering
  selected triangular-grid vertices. Each pit is about one six-triangle
  neighborhood wide, roughly 0.4 m across, with center target height in the
  0.91 m to 0.94 m range, just below the normal terrain lower bound.
- Terrain visual mesh: `image_cave_heightmap_terrain/meshes/sandstone_terrain_faceted.dae`.
- Terrain collision mesh: `image_cave_heightmap_terrain/meshes/sandstone_terrain_closed.stl`.
- Walls model: `image_cave_walls`.
- Surface block model: `image_cave_surface_blocks`.
- Lidar ceiling model: `image_cave_lidar_ceiling`.
- Surface block count: 200.
- Surface block size: 0.10 m x 0.13 m x 0.05 m.
- Surface block rotation: random yaw, random roll/pitch within 5 deg.
- Surface block placement: wall segments are rasterized into a 2D occupancy
  mask, then flood-filled from the rover spawn. Random block candidates are
  accepted only inside that spawn-connected corridor mask and still keep the
  near-wall and spawn-area clearance checks.
- Surface block height constraint: each accepted block is placed so its rotated
  bottom vertex sits about 0.002 m above the sampled terrain. Blocks skip pit
  bottoms so that pits remain visible and traversable as depressions.
- Ceiling: a fully transparent, non-shadowing triangular mesh derived by
  flipping the same generated cave floor height field upward. The nominal lower
  surface is z=2.19 m at the base terrain height; with the current terrain and
  pits, the lower surface spans about z=2.14 m to z=2.28 m. Collision and laser
  retro data remain enabled so lidar receives non-planar ceiling returns without
  the ceiling blocking lighting or map viewing.
- RViz collision layer: `/simulation/world_collision_markers` visualizes the
  lightweight collision geometry for the currently launched world. For
  `image_cave`, this includes 186 wall boxes, 200 surface block boxes, plus
  RViz-only pit markers from `image_cave_heightmap_terrain/metadata/pits.csv`.
  The floor and inverted-ceiling mesh collisions are intentionally omitted from
  the marker layer to avoid overloading RViz.
- RViz world/collision marker alignment: static Gazebo world geometry is
  transformed into the `map` frame using the rover's initial world pose. The
  marker publisher receives `map_origin_world_x/y/z/yaw`. In the standard
  gated restart script, XY/yaw come from `SPAWN_X`, `SPAWN_Y`, and `SPAWN_YAW`.
  Z comes from `MAP_ORIGIN_Z` when explicitly set; otherwise it defaults to the
  Gazebo spawn height. If the marker layer is vertically offset from the mapped
  point cloud, adjust only `MAP_ORIGIN_Z` or the collision marker offset rather
  than changing the Gazebo spawn height.
- The gated restart script and integrated FAST-LIO launch currently apply an
  RViz-only collision marker offset of `0.20` m by default for every world.
  Override it with `COLLISION_MARKER_Z_OFFSET` in the restart script or
  `collision_marker_z_offset:=...` in launch. This is a direct visualization
  patch for `/simulation/world_collision_markers` and does not move Gazebo's
  physical collision bodies.
- Cave pit markers in `/simulation/world_collision_markers` use the same cyan
  color as the collision layer but with `pit_marker_alpha=0.10`, so the pit
  discs remain visible without hiding the point cloud and map layers below.
  Collision outlines use a `0.010` m line width in the standard launch scripts.
- Default rover spawn: `x=-3.92`, `y=0.0`, `z=1.45`, `yaw=0.0`.

Use the full default bringup with:

```bash
ros2 launch lunar_rover_bringup bringup.launch.py \
  mode:=sim gui:=true rviz:=true sensor_noise:=false
```

Equivalent explicit world selection:

```bash
ros2 launch lunar_rover_bringup bringup.launch.py \
  mode:=sim world:=image_cave gui:=true rviz:=true sensor_noise:=false
```

`terrain_preview` is a lightweight Gazebo-only preview world for inspecting the
same terrain and wall models without spawning the rover or ROS controllers:

```bash
export IGN_GAZEBO_RESOURCE_PATH=/home/phragmund/LunarRover/install/lunar_rover_simulation/share/lunar_rover_simulation/models:/home/phragmund/LunarRover/src/lunar_rover_simulation/models
export GZ_SIM_RESOURCE_PATH=$IGN_GAZEBO_RESOURCE_PATH
ign gazebo -r -v 2 /home/phragmund/LunarRover/src/lunar_rover_simulation/worlds/terrain_preview.sdf
```

`image_cave` also has an optional generated centerline patrol route for Nav2:

- Route CSV:
  `src/lunar_rover_navigation/routes/image_cave_centerline_loop.csv`
- Preview image:
  `tmp/image_cave_centerline_loop_preview.png`
- The route is a closed centerline walk over the spawn-connected cave corridor
  skeleton. Dead-end channels are covered by entering and returning along the
  same centerline, then the route continues through the rest of the cave.
- CSV columns `x`, `y`, and `yaw` are in the RViz/Nav2 `map` frame for the
  default cave spawn pose. `x_world`, `y_world`, and `yaw_world` keep the
  corresponding Gazebo world coordinates.

Regenerate the route after changing cave wall topology or scale:

```bash
ros2 run lunar_rover_navigation generate_image_cave_centerline_route.py
```

Run the route follower after Nav2 is active:

```bash
ros2 run lunar_rover_navigation image_cave_waypoint_follower.py
```

Other available worlds:

`reachable_maze` also has a fully transparent, non-shadowing ceiling collision
box aligned above its maze walls. It remains invisible to normal viewing and
lighting, while collision and laser retro data are enabled for lidar returns.

| World | Contents | Typical use |
| --- | --- | --- |
| `flat` | Flat lunar ground plane. | Sensor, controller, and spawn smoke tests. |
| `steps` | Flat ground plus step-course geometry. | Suspension and step traversal tests. |
| `rocks` | Flat ground plus scattered small and medium rocks. | Obstacle contact and perception checks. |
| `mixed` | Combined basic terrain elements. | General low-risk integration testing. |
| `stairs_maze` | Maze-like walls plus stair/step features. | Structured navigation and obstacle handling. |
| `reachable_maze` | Generated maze with guaranteed reachable corridors. | Mapping and path-planning regression tests. |
| `lava_tube` | Procedural lava-tube corridor world. | Cave-like sensor and exploration tests. |
| `image_cave` | Reference-image cave topology with triangular terrain. | Default full-system test map. |
| `terrain_preview` | Same cave terrain and wall models, no rover required. | Fast visual inspection in Gazebo. |

Regenerate the image cave world and its reusable terrain/wall models with:

```bash
python3 src/lunar_rover_simulation/scripts/generate_image_cave_world.py
colcon build --symlink-install --packages-select lunar_rover_simulation
```
