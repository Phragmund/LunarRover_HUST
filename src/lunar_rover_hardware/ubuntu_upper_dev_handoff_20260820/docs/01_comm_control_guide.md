# LunarRover 上下位机通信与控制说明

## 1. 当前实机连线与编号约定

以 2026-08-20 联调结果为准：

- H7 与电脑：USB CDC 虚拟串口
- 四个 3508 行走电机：全部挂在 `CAN1`
- 四路舵电机控制板：接 H7 `UART7`
- 机械臂舵机控制板：接 H7 `UART10`

四轮统一编号顺序：

1. `1` = 右后
2. `2` = 左后
3. `3` = 右前
4. `4` = 左前

舵轮电机也使用同一顺序。

3508 当前方向表已经在下位机中固化为：

- `1` 右后：正向
- `2` 左后：反向
- `3` 右前：反向
- `4` 左前：正向

这是为了匹配当前实机安装方向后的最终结果。

## 2. 串口与总线参数

### 2.1 电脑 <-> H7

- 物理接口：USB CDC
- 上位机工具打开时一般按 `115200` 配置
- 本质上是 USB 虚拟串口，主机侧仍建议统一按 `115200 8N1`

### 2.2 H7 <-> 四路舵电机板

- 端口：`UART7`
- 波特率：`115200`
- 引脚：
  - `PE7` = `UART7_RX`
  - `PE8` = `UART7_TX`

### 2.3 H7 <-> 机械臂控制板

- 端口：`UART10`
- 波特率：`115200`
- 引脚：
  - `PE2` = `USART10_RX`
  - `PE3` = `USART10_TX`

### 2.4 H7 <-> 3508

- 总线：`FDCAN1 / CAN1`
- 3508 ESC ID：`1..4`

## 3. 上位机到 H7 的总协议入口

电脑只需要连一个 H7 USB CDC 串口。

H7 会在 USB CDC 上同时接收三类命令：

- `3508`：前缀 `$M3508:`
- `舵轮`：前缀 `$ANG` / `$SPD` / `$STOP` / `$ZERO`
- `机械臂`：前缀 `$ARM:`

建议上位机采用“单串口集中调度”的方式，不要再分别去直连各个机构。

## 4. 3508 控制协议

### 4.1 支持命令

- 速度模式，单位 `输出轴 r/s`
  - `$M3508:SPD,s0,s1,s2,s3!`
- 速度模式，单位 `输出轴 rpm`
  - `$M3508:RPM,r0,r1,r2,r3!`
- 位置模式，单位 `输出轴 deg`
  - `$M3508:POS,a0,a1,a2,a3!`
- 电流模式，单位 `C620 raw current`
  - `$M3508:CUR,c0,c1,c2,c3!`
- 停止
  - `$M3508:STOP!`
- 当前位置设为零位
  - `$M3508:ZERO!`
- 使能/失能
  - `$M3508:ENABLE,1!`
  - `$M3508:ENABLE,0!`

### 4.2 反馈

H7 周期发送：

`$M3508:FB,enabled,mode,onlineMask,a0,a1,a2,a3,s0,s1,s2,s3,g0,g1,g2,g3,f0,f1,f2,f3,t0,t1,t2,t3!`

字段说明：

- `enabled`：当前命令使能状态
- `mode`：当前模式枚举
- `onlineMask`：4 路在线位掩码，16 进制文本
- `a0..a3`：角度，缩放为 `0.1 deg`
- `s0..s3`：速度，缩放为 `0.001 r/s`
- `g0..g3`：下位机输出给 ESC 的电流命令
- `f0..f3`：ESC 回读电流
- `t0..t3`：温度

### 4.3 下位机控制特点

- 3508 控制任务周期：`10 ms`
- 命令超时：`500 ms`
- 遥测周期：`100 ms`
- 3508 自身会在第一次有效反馈时自动建立位置零点基准

## 5. 舵轮控制协议

### 5.1 上位机命令

- 角度模式，单位 `deg`
  - `$ANG,a0,a1,a2,a3!`
- 速度模式，范围一般按 `-1..1`
  - `$SPD,s0,s1,s2,s3!`
- 停止
  - `$STOP!`
- 当前机械位置置零
  - `$ZERO!`
- 透传四路板原始指令
  - 例如：`$MOTOR_4CH_READ:encoder_total!`

### 5.2 下位机行为

H7 本身做位置闭环，四路板主要接收速度指令 `$Car:x,x,x,x!`。

当前下位机的重要行为：

- 位置模式命令超时：`2 s`
- 速度模式命令超时：`200 ms`
- 上电后，每一路在首次拿到有效编码器反馈时，会自动把“当前机械位置”设为零位
- 位置模式是“单发目标，H7 自己保持到位”，不是要求上位机持续重发同一角度

### 5.3 反馈

H7 周期发送：

`$STD,fb0,fb1,fb2,fb3,ang0,ang1,ang2,ang3,target0,out0,isr0,online0,tx0`

注意：

- 这份 `$STD` 遥测目前只完整暴露了 `通道0` 的目标角、输出速度和部分诊断计数
- 4 路角度 `ang0..ang3` 都有
- `fb0..fb3` 表示是否收到过反馈
- 上位机如果要做完整舵轮状态机，建议后续扩展协议，而不是长期依赖当前 `$STD` 的简化格式

### 5.4 频率特性

- 舵轮任务周期：`20 ms`
- 编码器请求周期：约 `60 ms`
- 速度下发周期：约 `40 ms`
- 文本遥测周期：`100 ms`

## 6. 机械臂控制协议

### 6.1 上位机命令

- 心跳
  - `$ARM:PING!`
- 读取单个舵机位置
  - `$ARM:READ,1!`
- 单舵机移动
  - `$ARM:MOVE,id,pulse,time!`
- 停止
  - `$ARM:STOP,id!`
- 扭矩开关
  - `$ARM:TORQUE,id,1!`
  - `$ARM:TORQUE,id,0!`
- 多舵机联动
  - `$ARM:MULTI,id1,pulse1,id2,pulse2,...,time!`
- 原始透传
  - `$ARM:RAW,#001PRAD!`

### 6.2 返回格式

- 启动信息
  - `$ARM:BOOT,UART10,115200!`
- 心跳应答
  - `$ARM:OK,PONG!`
- 读取位置返回
  - `$ARM:RESP,#001P1500!`
- 其他动作一般返回 `$ARM:OK,...!`
- 错误返回 `$ARM:ERR,...!`

### 6.3 原始舵机协议

H7 到舵机板透传的是松嘉风格协议，常见例子：

- 单舵机移动：`#001P1500T1000!`
- 读取位置：`#001PRAD!`
- 停止：`#001PDST!`
- 扭矩开：`#001PULR!`
- 扭矩关：`#001PULK!`
- 多舵机联动：`{#001P1500T1000!#002P1500T1000!...}`

### 6.4 机械臂关节约定

当前网页工具中的关节定义：

- `j1` = ID 1，正常
- `j2` = ID 2，反向
- `j3` = ID 3，正常
- `j4` = ID 4，反向
- `j5` = ID 5，正常，夹爪

Home 姿态：

- `j1=90`
- `j2=180`
- `j3=135`
- `j4=135`
- `j5=45`

## 7. 上位机开发建议

### 7.1 推荐架构

- 一个串口管理器，独占 H7 USB CDC
- 三个逻辑模块：
  - `m3508_client`
  - `steer_client`
  - `arm_client`
- 一个统一的 RX 分发器，按前缀分流：
  - `$M3508:`
  - `$STD,`
  - `$ARM:`

### 7.2 不建议的做法

- 不要让多个进程同时抢占同一个 CDC 串口
- 不要把“位置模式持续重发”作为最终控制架构
- 不要再直接把电脑分别连到四路板或机械臂板，除非做底层故障诊断

### 7.3 Ubuntu 侧最小依赖

- `python3`
- `python3 -m http.server`
- 浏览器：`Chromium` 或 `Google Chrome`
- 如果需要 CLI 串口调试：`pyserial`
